我想验证一件事：给 AI 一句话，让它**自主**开发一个游戏玩法的自动化，我能尽量不插手吗？这是系列第一篇，记 day1——AI 怎么从一句话起步，摸清一个它训练数据里压根没有的新玩法。

有意思的是，它拿到任务后第一件事，不是打开 IDE 写代码。

<!-- more -->

## 实验背景：为什么我敢"放手"

我手上有个开源项目「星穹铁道一条龙」（StarRailOneDragon），Python 写的游戏自动化框架。它有一层 **harness**：通过 MCP 把游戏操作暴露给 AI agent——能截图、能点游戏、能按键、能跑代码、能读写项目文件。agent 是 Claude Code，挂在这个 MCP 后端上。

有了这层接入，agent 不再只是"读代码、改代码"，它能**亲自驱动游戏**：看一眼画面 → 动一下 → 等一下 → 再看一眼验证。这个"看→动→等→验"的短闭环，是后面一切的地基。

我想拿星铁 3.7 的新玩法「货币战争」（类自走棋肉鸽：金币招角色 → 配阵容 → 出战 → 战斗全自动 → 凑羁绊/管经济 → 结算）做个实验：**只给 AI 一句话，让它自己把自动化做出来，我尽量不插手。**

## 我给的一句话

> 自主完成货币战争自动化的 app。

一个训练有素的工程师拿到这句话，第一反应不是打开 IDE，而是先问：「货币战争」是什么？是常驻还是限时？机制是什么？有没有兄弟功能可以抄？

我想知道 AI 会不会也这样。结果它出乎意料地对。

## AI 的第一步：没写代码，先搜"这玩意儿还在不在"

AI 第一件事不是写代码，而是去 web 搜——而且优先查的**不是"怎么玩"，而是"是常驻还是限时"**。

为什么这条决定整个项目的形态：

- 若是**限时活动**，现在是 2026-08，大概率已结束 → 只能做"研究 + 代码骨架"，**没法实机验证**（对象过期了）。
- 若是**常驻**，能实机跑、实机抓 bug、实机验证。

搜出来（米哈游官方 + 攻略）：货币战争是 3.7 版大型常驻玩法，赛季制，和模拟宇宙交替更新，非限时。门槛解除——能做实机验证，不是纸上谈兵。

> **心得**：自主开发一个**外部依赖**（游戏玩法）时，先验"这个依赖现在还在不在、能不能碰"比钻研机制更重要。机制再懂，对象过期了也白搭。这是 AI 特别容易漏的「现实约束前置检查」——它倾向于直接钻机制，得有意识地把它拽回来先问"还在不在"。

## 找"结构同构"的兄弟，而不是从零设计

机制也顺手搞清了：类自走棋肉鸽 + 选择决策 + 自动战斗。AI 的下一个判断很关键：这跟项目里**已有的「模拟宇宙」（sim_universe）结构同构**——都是肉鸽推进 + 选择类决策（祝福/奇物 ↔ 角色牌/羁绊）+ 自动战斗 + 指南传送入口。

→ 直接定了模板：**复用 sim_universe 的架构骨架**（entry 入口 + 选择类 op + 自动战斗 + 结算），只换业务细节。sim_uni 里现成的"选择类 op"（OCR 识别选项 → 优先级选取 → 点击）就是货币战争"投资环境 3 选 1 / 商店买牌"的直接参照。

而且它识别出一点：货币战争是**节点制、无大世界移动**，所以 sim_uni 大量的寻路代码**用不上，也不该照搬**。复用对的、丢掉不对的。

> **心得**：面对陌生玩法，AI 的杠杆不是"更聪明"，而是"在既有代码里找结构同构的兄弟"，复用架构骨架、只换业务细节。比从零设计省一个数量级，也更符合工程现实（项目本来就要求先复用现有模式）。

## 跟着玩一遍，胜过读十篇攻略

搞清架构后，AI 没止步于"看攻略"。它**实际驱动游戏，从入口一路点到核心画面**：ESC 开菜单 → 指南 → 旷宇纷争 → 货币战争 → 前往参与 → 关弹窗 → 大厅 → 开始 → 标准博弈 → 开始对局 → 位面简报 → 投资环境选择 → 备战阶段 → 商店。

走完一遍，auto-chess 的循环（读牌 → 买牌 → 配阵 → 出战 → 自动战斗 → 选事件 → 下一节点 → 首领 → 结算）自然浮现。而且**每一步都留了截图 = 建档素材**——8 个画面、入口路径、大厅/商店所有可交互元素，全记进了项目的 gameplay 文档。

这靠的是 harness 给的 **MCP 操作三件套**：看（`analyze_screen` 截图 + OCR）→ 动（`click_game` / `key_tap`）→ 等（sleep）→ 验（再截一张）。没有这层"把游戏操作暴露给 agent"的接入，agent 只能看代码、看静态截图，**不能亲自跑一遍**——而跑一遍，是这个玩法建档最快的方式。

> **心得**：对"流程类"玩法，AI 与其反复读描述，不如**亲自跑一遍**。跑一遍胜过读十篇攻略，副产品（截图）直接就是建档产出。

## day1 成果：入口流程跑通（固定位置，无策略）

day1 这部分出乎意料地顺：入口 op 写完，`run_operation` 实机跑，**4 秒出结果**。AI 抓了几个 bug 改掉（OCR 把指南页的"货币战争"文本误判成大厅按钮的"假成功"；状态机自环导致的死循环），两轮就把入口跑通。最终 `run_standalone_app('currency_war')` 端到端 23.7 秒验证通过：大世界 → 货币战争大厅 → 开始对局 → 备战阶段，干净终止。

这部分"容易"，是因为它全是**固定位置的点击和导航**——agent 复用 sim_uni 模板 + MCP 操作三件套，很快搞定。**但完全没策略**：它只是"能到备战"，不知道该买哪些牌、怎么配阵、怎么打赢。

## 复盘：day1 为什么顺，day2 为什么会崩

day1 顺，是因为地基好：harness 给了 agent "亲自跑一遍"的能力，项目里有结构同构的兄弟可抄，always-on 的方法论让它不漂移。这些让"探索 + 入口"这种**流程性、位置固定**的任务很快拿下。

但 day1 的"能跑"是个假象。真正的硬骨头在 day2：识别画面里**没有文字的元素**（角色立绘）、把复杂流程**拆成可维护的代码**、制定**策略**——这些 day1 一个没碰到。

下一篇就记 day2 AI 绕的最大一个弯：让它用视觉模型"量坐标"，它翻车翻到离谱，绕了一整条路最大的弯路才找到根因。那个弯路，和它"不查文档凭猜试错"的毛病，是 day2 的开场。
