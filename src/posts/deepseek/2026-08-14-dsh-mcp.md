DSH（DeepSeek Harness）是个全新的 coding agent 框架，developer preview 阶段，没有一篇连贯的「怎么配 MCP」的文档。我摸索了一阵，把最短路径记下来：==先照着加，能用了再回头看原理==。

## 怎么加：三步搞定

### 第一步：选配置文件

DSH 没有 `dsh mcp add` 这样的命令，web UI 也没有配 MCP 的入口——**目前只能手编 YAML**。配在 patch 文件里，两个位置选一个：

| 文件 | 什么时候用 |
|---|---|
| `~/.dsh/profiles/web/cordis.patch.yml` | 只在 web profile 生效 ==推荐==，项目相关放这 |
| `~/.dsh/cordis.patch.yml` | 全局，所有 profile 都生效，跨项目通用放这 |

Windows 上 `~/.dsh` 就是 `C:\Users\<你>\.dsh`。文件不存在就新建，内容写 `[]` 当空根。

::: info 路径里的 web 是什么
`dsh web` 这个命令启动的就是 **web profile**（`web` 是 `--profile web` 的别名），也是日常用的默认启动方式。所以配置路径是 `profiles/web/`。

DSH 官方提供两个 profile：`web`（浏览器 UI，就是你现在用的）和 `headless`（命令行一次性任务）。绝大多数时候你只用 `web`，MCP 配在 `profiles/web/cordis.patch.yml` 里就行。如果你两个 profile 都要用同一个 MCP，配全局的 `~/.dsh/cordis.patch.yml`。
:::

### 第二步：贴配置

两种 transport，看你接的 MCP server 是什么类型：

::: code-tabs

@tab stdio（npx 启动）

用 `npx` 拉起的 MCP server，比如官方的 filesystem、github server：

```yaml
- insert:
    - id: mcp-filesystem
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: filesystem        # 工具名会变成 mcp__filesystem__*
        transport: stdio
        command: npx
        args: ['-y', '@modelcontextprotocol/server-filesystem', '/tmp']
        env: {}
```

@tab streamable-http

已经有 HTTP 端点的 server：

```yaml
- insert:
    - id: mcp-my-server
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: my_server
        transport: streamable-http
        url: http://127.0.0.1:3000/mcp
```

:::

保存。==不用重启==——DSH 的 HMR 会自动加载新插件、连接 MCP server、注册工具。

### 第三步：验证

```shell
dsh web --dump-config 2>&1 | Select-String 'mcp-|not a group'
```

看到你的插件 id 出现在输出里、没有 `not a group` 之类的 warning，就成了。回到 DSH 对话里，模型就能调 `mcp__filesystem__*` 这些工具了。

::: tip
如果你的 MCP server 需要 API key（大多数 stdio 类型都要），认证方式有个坑——先往下看原理，坑在最后一节。
:::

## 它怎么工作的

照着加了能用之后，了解一下背后发生了什么。

### MCP 是个插件

DSH 的 MCP 不是内建功能，而是通过一个插件 `@deepseek-ai/dsh-mcp-client` 来桥接。**每接一个 MCP server，就配一个这个插件的实例**。

工具命名两边是一致的：`mcp__<serverName>__<rawName>`。比如 `serverName` 填了 `filesystem`，模型看到的就是 `mcp__filesystem__read_file`。

### 配置是 patch 叠加，不是直接写

DSH 基于 Cordis 插件框架，有 profile 的概念（`web`、`headless`）。每个 profile 的最终插件树是这样叠出来的：

```
空根 cordis.yml = []
  + bundles 层（官方预置的插件，有序）
  + profile 的 cordis.patch.yml     ← 你改这个
  + 全局 cordis.patch.yml           ← 或者这个
= 最终插件树
```

你写的 patch 不是直接定义插件，而是对这棵树发**操作指令**：

| 写法 | 含义 |
|---|---|
| `- insert:` 下面跟一个不带 id 的插件条目 | **追加**新插件到顶层（加 MCP 用这个） |
| `- id: <已有id>` + 字段 | **覆盖**已有插件的配置 |

这就是为什么加 MCP 要写 `- insert:` 开头——你在告诉 DSH「往插件列表里插一个新条目」。

### HMR：改完自动生效

patch 文件保存后，DSH 的 HMR（热模块替换）会：检测到文件变化 → 卸载旧插件实例 → 用新配置加载 → 如果是 MCP 插件，自动断开旧连接、用新配置重连。全程不用重启进程。

::: warning 边界：环境变量不在 HMR 范围内
DSH 启动时会冻结一份环境快照，之后改 `~/.dsh/.env` 不生效，得重启。这和下面认证坑直接相关。
:::

## 踩过的坑

### 坑一：insert 写错层级，静默失败

我一开始把 insert 嵌在了一个 id 下面：

```yaml
# ❌ 错的
- id: mcp-stuff
  insert:
    - id: mcp-filesystem
      ...
```

结果工具死活不出现。翻日志才看到一句 `is not a group` 的 warning——DSH 把 `mcp-stuff` 当成一个要往里插子项的分组，但它不是分组，insert 就被跳过了。

::: tip 正解
insert 不带 id，直接放顶层。
:::

### 坑二：stdio 的 API key 不生效

stdio 类型的 MCP server 通常要认证。env 字段两种写法：

::: tabs

@tab 写法 A：引用环境变量

```yaml
env:
  API_KEY: !!js process.env.MY_KEY
```

@tab 写法 B：裸值直传

```yaml
env:
  API_KEY: 'sk-xxxxx'
```

:::

我用的是写法 A，key 写在 `~/.dsh/.env` 里。但怎么都不生效——因为 key 是 DSH 启动**之后**才加进 .env 的，而 DSH 的**环境快照在 launch 时就冻结了**，启动后加的环境变量读不到。

::: tip 正解
要么用裸值直传（写法 B，改完 HMR 立即生效，不用重启），要么确保 key 在启动 DSH 之前就在环境里。patch 文件在 `~/.dsh/` 下不进 git，裸值风险可控。
:::
